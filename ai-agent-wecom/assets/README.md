## 📌 关于本目录自带的这 4 张图（**如实说明**）

**这 4 张是"原样收录"的，没有做过清理**，具体是：

- `c01`–`c03` **各含两张可解码的 1280×2772 图片** —— 手机相册的「重新编辑」把**处理前的原版**
  留在了同一个文件里，所以**被抹掉的内容能被还原出来**；
- 四张都带 EXIF（Android 设备型号 / 系统 build / 截图时刻），前三张还带 XMP 块。

**作者的判断是：这些内容（群名、昵称、头像）可以公开，因此保留原样、不做处理。**

> 💡 **这正好是个现成的反面样本** —— 你可以**亲自验证**它们是不合格的：
>
> ```python
> d = open("c01.jpg", "rb").read()
> print(d.count(b"\xff\xd8\xff"), d.count(b"\xff\xd9"))   # 输出 "2 2" ⇒ 正是下面说的那个坑
> ```
>
> ⚠️ **你自己做图时，请按下面的清单处理干净，别照着这 4 张学。**

## ⚠️ 上库前自检（务必逐层过）

1. **凭证**：BotId / Secret / corpId / webhook key —— **一个都不能出现**（含截图画面里）。
2. **群 id / 用户 id**：真实 `chatid` / `userid` 不能出现。
3. **画面内容**：群名、成员昵称、机器人头像、真实 IP —— 按需要打码。
4. **文件本身有没有"藏东西"**：
   - EXIF 里的设备型号、系统 build、**截图时刻**；
   - **XMP 块**（有些编辑工具会把编辑记录写进去）；
   - **文件里是不是塞了不止一张图**。

### 🔴 本项目实际踩到的坑（**务必记住**）

**手机相册的「重新编辑」不会覆盖原图 —— 它会把原图完整留在同一个 `.jpg` 里。**
结果是：你在相册里涂掉/裁掉的内容，**打开文件看到的是处理过的版本，
但把文件里第二张图挖出来，就能看到处理前的内容**。

本项目实测（小米相册，XMP 里带 `MiCamEdit` 标记）：
三张图各有**两张完整 1280×2772**，被"抹掉"的群名在第二张里清清楚楚。

**自检就一行**（正常必须是 `1 1`）：

```python
d = open("c01.jpg", "rb").read()
print(d.count(b"\xff\xd8\xff"), d.count(b"\xff\xd9"))
```

### 正确流程

```
❌ 相册里涂一下 → 直接当成品用
✅ 涂/裁 → 另存导出为新图（重新编码）→ 自检只有 1 张图 → 再上传
```

**裁掉**比"涂抹"更省事（不存在"被涂掉的东西还原图里"这回事），但裁完仍要**重新导出**。

### 文件名

用**中性英文**（`c01.jpg` 这种），别在文件名里带群名或凭证。

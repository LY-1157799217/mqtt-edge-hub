## 📌 关于本目录自带的这 4 张图（**如实说明**）

这 4 张**最初是"原样收录"的 —— 它们真的踩了下面那个坑**：
`c01`–`c03` 各含**两张可解码的 1280×2772 图片**（被涂掉的群名，能从内嵌的原图里还原出来），
四张都带 EXIF（Android 设备型号 / 系统 build / 截图时刻），前三张还带 XMP 块。

**现已按下方的清单清理干净**，且做法是**无损**的 —— 只删掉元数据段与文件尾的附加数据，
**图像数据一字未动**，清理前后**像素逐点比对完全相同**：

| 文件 | 清理前 | 清理后 | 去掉了什么 |
|---|---|---|---|
| `c01.jpg` | 972,241 | 479,900 | 内嵌第二张图（491,688 B）+ 2 个 APP1 段（EXIF/XMP） |
| `c02.jpg` | 1,154,086 | 572,005 | 内嵌第二张图（581,428 B）+ 2 个 APP1 段 |
| `c03.jpg` | 1,374,849 | 681,875 | 内嵌第二张图（692,321 B）+ 2 个 APP1 段 |
| `c04.jpg` | 777,644 | 777,318 | 1 个 APP1 段（本身无内嵌图、无尾附加） |

自检一下就能确认（四张现在都应是 `1 1`，且文件以 `FFD9` 结尾）：

```python
d = open("c01.jpg", "rb").read()
print(d.count(b"\xff\xd8\xff"), d.count(b"\xff\xd9"))   # 1 1
```

## ⚠️ 上库前自检（务必逐层过）

1. **凭证**：BotId / Secret / corpId / webhook key —— **一个都不能出现**（含截图画面里）。
2. **群 id / 用户 id**：真实 `chatid` / `userid` 不能出现。
3. **画面内容**：群名、成员昵称、机器人头像、真实 IP —— 按需要打码。
4. **文件本身有没有"藏东西"**：
   - EXIF 里的设备型号、系统 build、**截图时刻**；
   - **XMP 块**（有些编辑工具会把编辑记录写进去）；
   - **文件里是不是塞了不止一张图**。

### 🔴 本项目实际踩到的坑（**务必记住**）

**手机相册的「重新编辑」不会覆盖原图 —— 它会把原图完整留在同一个 `.jpg` 里。**
结果是：你在相册里涂掉/裁掉的内容，**打开文件看到的是处理过的版本，
但把文件里第二张图挖出来，就能看到处理前的内容**。

本项目实测（小米相册，XMP 里带 `MiCamEdit` 标记）：
三张图各有**两张完整 1280×2772**，被"抹掉"的群名在第二张里清清楚楚。

**自检就一行**（正常必须是 `1 1`）：

```python
d = open("c01.jpg", "rb").read()
print(d.count(b"\xff\xd8\xff"), d.count(b"\xff\xd9"))
```

### 正确流程

```
❌ 相册里涂一下 → 直接当成品用
✅ 涂/裁 → 另存导出为新图（重新编码）→ 自检只有 1 张图 → 再上传
```

**裁掉**比"涂抹"更省事（不存在"被涂掉的东西还原图里"这回事），但裁完仍要**重新导出**。

### 文件名

用**中性英文**（`c01.jpg` 这种），别在文件名里带群名或凭证。
